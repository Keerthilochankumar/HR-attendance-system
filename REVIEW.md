# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Top-level config (lines 22-23) | Hard-coded default fallback URIs (`mongodb://localhost:27017`, `attendance_db`). Problem statement explicitly forbids hardcoded credentials. | Unset `MONGO_URI` in production; app silently connects to local MongoDB instead of failing fast. | Enforced environment variable validation at startup; raises `RuntimeError` if `MONGO_URI` or `MONGO_DB` is missing. |
| 2 | `MongoClient` initialization (line 22) | Missing `tz_aware=True`. PyMongo defaults to returning naive datetimes in UTC, causing timezone mixing bugs. | Performing date-time arithmetic between PyMongo dates and aware `datetime` objects crashes with `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Configured client with `tz_aware=True` and normalized all boundary inputs to UTC with microsecond truncation. |
| 3 | Startup / DB setup (lines 22-28) | Zero database indexes defined or created at startup. | At scale (~100k documents), queries trigger COLLSCAN, and concurrent inserts cannot guarantee uniqueness. | Defined `INDEX_SPECS` with unique and compound indexes; ensured idempotent index creation via `ensure_indexes_once` at startup. |
| 4 | `GET /health` (lines 72-74) | Dummy endpoint returning hardcoded `{"status": "ok"}` without checking database connectivity. | Stop or disconnect MongoDB; `/health` continues to return 200 OK instead of 503 Service Unavailable. | Added `await db.command("ping")`; mapped `ConnectionFailure` to HTTP 503 `ServiceUnavailableError`. |
| 5 | `compute_late_minutes` (lines 33-37) | Checked `minutes > 10` where `minutes = int((punch_in - start).total_seconds() / 60)`. At 10m01s (601s, e.g. 09:40:01 for 09:30 shift), `int(601/60)=10`; `10 > 10` is False, returning 0 instead of 10. Also ignored IST and overnight shifts. | Input punch-in at `09:40:01` for shift `09:30` (example in R2 spec) yielded 0 late minutes instead of 10. | Replaced with `elapsed_seconds > 600`, returning `elapsed_seconds // 60` if late else 0, calculated against the IST shift start. |
| 6 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round()`, which performs banker's rounding (round half to even) rather than round half-up required by R4. | Duration of 2.675 hours rounded to 2.67 instead of 2.68. | Implemented exact half-up rounding using `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 7 | `compute_overtime` (lines 44-47) | Did not enforce the R3 30-minute threshold (returned any positive minutes < 30). Subtracted naive/aware datetimes (`TypeError`). Ignored that overnight shifts end on the next calendar day. | Punch-out 5 minutes after shift end returned 5 overtime minutes instead of 0. Naive/aware mismatch crashed with `TypeError`. | Added `minutes >= 30` threshold (else 0); aligned timezones; added +1 day to shift end for overnight shifts (`shift_end <= shift_start`). |
| 8 | Instants handling (lines 33-47, 102) | Microseconds were not truncated to whole seconds prior to calculation (violating rule R1). | Timestamps like `09:40:00.900` were processed with microsecond fractions rather than whole seconds. | Truncated all instant inputs to whole seconds (`replace(microsecond=0)`) at API boundaries prior to storing or computing. |
| 9 | `EmployeeIn` schema (lines 53-60) | Missing schema constraints: lacked regex for `emp_code`, email pattern, department length, and did not check `shift_start != shift_end`. | Invalid employee codes like `"xyz"` or identical shift times (`09:30` to `09:30`) were accepted with 201 Created. | Added Pydantic regex patterns, length limits, and a model validator ensuring `shift_start != shift_end`. |
| 10 | `POST /employees` (lines 78-85) | Check-then-insert (`find_one` then `insert_one`) subject to race conditions under concurrent requests. `created_at` used naive local time and was returned as unformatted datetime. | Concurrent requests with identical `emp_code` created duplicate documents. Response leaked internal datetime object. | Enforced unique index on `emp_code`; caught `DuplicateKeyError` and raised 409; converted `created_at` to epoch milliseconds. |
| 11 | `GET /employees` (lines 88-96) | Pagination used `skip = page * page_size`, skipping the first page (`page=1` skipped 20 items). `total` counted `{}` ignoring department filter. Missing sort on `emp_code` asc. | Requesting `page=1` missed the first 20 employees. `total` did not reflect filtered department. | Set `skip = (page - 1) * page_size`; used `count_documents(query)`; added `.sort("emp_code", 1)`. |
| 12 | `PunchInIn` schema (lines 63-67) | `punched_at` had no lower bound check, accepting seconds instead of milliseconds. `status` accepted arbitrary strings. | Supplying `punched_at: 1783312500` (seconds) or `status: "INVALID"` succeeded with 201 Created instead of 422. | Added `EpochMillis` strict validation (`>= 100000000000`) and restricted `status` to `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 13 | `POST /attendance/punch-in` (lines 99-102) | Accessing `emp["shift_start"]` without verifying employee existence resulted in `TypeError` (500 Internal Server Error). | Punch-in for non-existent `emp_code` returned 500 instead of 404. | Added `get_employee_or_404` check; raised 404 `NotFoundError` when employee is missing. |
| 14 | `POST /attendance/punch-in` (lines 102-103) | Attendance date was determined from server-local naive time instead of IST calendar date, breaking overnight shifts (R1). | Overnight punch-in at 02:00 IST for a 22:00 shift was assigned to the current day instead of previous day. | Implemented `attendance_date` helper converting to IST and subtracting 1 day for early morning punches on overnight shifts. |
| 15 | `POST /attendance/punch-in` (lines 104-118) | Check-then-insert race condition. Two simultaneous punch-ins for the same employee and date could both pass `find_one`. | Concurrent punch-ins resulted in duplicate records. | Relied on MongoDB unique compound index on `(emp_code, date)`; caught `DuplicateKeyError` returning 409. |
| 16 | `POST /attendance/punch-in` (lines 118-121) | Injected disallowed `id` field into response; returned raw datetime objects instead of epoch milliseconds. | Response failed OpenAPI schema validation due to illegal `id` property and datetime strings. | Removed `id` field injection; converted `punch_in` to epoch milliseconds integer. |
| 17 | `GET /attendance` (lines 124-150) | Loaded entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorted in Python. Inverted date ranges were not validated. | Out-of-memory crash on 100k records; `date_from > date_to` returned 200 with empty list instead of 422. | Pushed pagination and sort `[("date", -1), ("emp_code", 1)]` down to MongoDB cursor; added 422 validation for inverted date ranges. |

### Items Examined and Decided Were NOT Defects
1. **Storing dates and shift times as strings (`YYYY-MM-DD`, `HH:MM`)**: Verified against `DATA_MODEL.md` that dates are deliberately stored as plain strings in IST to prevent timezone translation errors.
2. **Exclusion of `_id` in API responses**: Verified against `openapi.yaml` that MongoDB's internal `_id` is private and must never appear in API requests or responses.
3. **Environment variable loading precedence**: Verified that `load_dotenv(override=False)` ensures real environment variables properly override `.env`.
